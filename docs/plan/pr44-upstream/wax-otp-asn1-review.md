# Wax OTP ASN.1 compiler candidate

This is an **unreleased upstream candidate**, not an installed Kith dependency change. [The patch](wax-otp-asn1.patch) removes Wax 0.7.0's `asn1_compiler` dependency and uses OTP's maintained `:asn1ct` directly through a package-owned Mix compiler. Kith's ASN.1-helper maintenance blocker remains open until a genuine compatible Wax release is available and the application adopts and validates it.

The compiler preserves the previous options: default BER encoding, tuple records, `:noobj`, and generated sources in `src`. The Android-key verifier relies on those record shapes. All three Android schemas are unchanged; generated `.erl` and `.hrl` files are byte-identical to the old helper's output on the tested runtime. The patch packages its build task, records content/runtime fingerprints, invalidates prior success before regenerating any output, rebuilds missing outputs, cleans generated artifacts, and explicitly includes the OTP `:asn1` runtime application. It adds no Hex dependency and changes no attestation verifier or authentication policy.

Run from Kith's root:

```sh
./docs/plan/pr44-upstream/wax-otp-asn1-probe.sh /tmp/wax-otp-asn1-review
```

Use a fresh destination. The runner verifies the original Hex tarball checksum, applies the patch in isolated source copies, clears inherited build/dependency-directory overrides, and retains logs. It needs Python 3 with safe tar extraction, curl, patch, Elixir/Mix, and a complete OTP distribution. When `.tool-versions` exists, it copies that file into the temporary projects. No shared Kith `_build`, Git worktree, upstream write or package publication is involved.

The [recorded evidence](wax-otp-asn1-evidence.json) comes from Darwin 27.2.0 arm64, Elixir 1.19.5, OTP 28.5.0.5 / ERTS 16.4.0.5, ASN.1 5.4.3:

- Original, candidate, restored-source and mixed-failure-restored probes each pass four tests. The candidate decodes and re-encodes 48 synthetic records generated by the old implementation, across all three Android schema versions. Malformed encodings are rejected.
- Actual Wax APIs accept a newly signed ES256 packed self-attestation registration and a signed authentication assertion; modified signatures, wrong origins and wrong RP hashes are rejected.
- Incremental, missing-output and clean rebuild checks pass. Corrupting a schema declaration fails compilation; restoring it passes. Appending text after ASN.1 `END` was an ineffective exploratory negative control because OTP ignores it; the retained runner corrupts the declaration itself.
- The partial-generation regression is reproduced against the earlier candidate: a valid V1 change writes altered output before malformed V2 fails; restoring both original schemas incorrectly reuses the old success manifest and compiles stale V1, causing one of four compatibility tests to fail. The fix removes the success manifest before regeneration and fails before writes if that removal fails. The retained runner repeats this mixed case, requires no surviving success manifest after failure, restores both schemas, verifies all three regenerated Erlang/header pairs exactly match the legacy output, and passes all four compatibility/signed-flow tests again.
- A fresh Hex package contains the compiler and schemas, with neither `src` nor `_build`. Its freshly extracted source compiles and builds a production release. That release repeats all 48 legacy schema round trips and the signed registration/assertion flow without Mix or ExUnit.
- The explicit-empty-ignore Hex audit passes. Installed Hex constraints match in both graphs. The standalone developer lock loses only `asn1_compiler`, with no new Hex dependency; the runtime Hex closure remains CBOR, Jason and X509. Wax's own dev documentation dependencies in the standalone lock are not inherited by Kith.

Remaining gates are upstream review/release, the declared runtime matrix, cold Linux/musl builds, and full Kith/WebAuthn validation after adoption. The Hex source does not include Wax's complete upstream tests. These probes do not establish physical-device or certificate-backed Android, TPM, FIDO-U2F or Apple attestation compatibility. No authentication service migration is proposed.
